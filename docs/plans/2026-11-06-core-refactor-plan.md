## 结论与范围

建议全面整理共享基础设施，但先保持现有发布包边界，在包内拆职责、跨包纠正所有权、合并重复能力。仅拆小文件不会解决依赖和状态问题；一次重写所有底层又容易破坏已经稳定的交互。

本轮不更换 X6、不重新设计界面、不改持久化格式、不直接把快照历史改为操作日志，也不先创建通用 contracts 包。新增发布包必须有独立消费者、清晰稳定接口或独立部署需要作为依据。本次获批的 `@flow-designer/i18n` 以纯服务消费者和可独立使用的 React adapter 为边界；其他发布包暂保持现状。

| 位置 | 当前职责问题 | 重构目标 |
| --- | --- | --- |

| `packages/plugins/src/x6-graph/bridge/graph-bridge.ts` | 图投影、手势采集与事务提交混合；部分代码读取可变 X6 cell | 类型化操作快照、统一编辑服务、独立投影协调 |

| `packages/engine/src/index.ts` | 广泛聚合导出，消费边界不够明确 | 保留便捷入口，逐步提供显式子入口和消费测试 |

## 目标职责与依赖

| 包 | 应保留/承接 | 应迁出/限制 |
| --- | --- | --- |
| model | Document、Content、Props、关系、领域定义、序列化、Timeline | 画布命令上下文、React 面板、浏览器偏好副作用 |
| core | Editor、通用命令总线、插件生命周期、实例服务、窄 GraphPort 与通知端口 | 不引入 React、X6 或具体 UI 实现；不承接场景业务 |
| graph | X6 适配、投影、几何计算、端口候选、路由、手势预览、视口 | 不直接写 Document 或拥有业务历史 |
| plugins | 可选编辑能力、应用命令实现、图与模型桥接 | 不跨适配边界读取可变 X6 cell，不自建全局注册补丁 |
| skeleton | Area/Pane UI 协议、共享 React 内容与扩展渲染 | 不负责领域模型和全局编辑运行时 |
| react | Workbench、面板、DOM/浏览器适配、通知实现 | 不重复实现创建、连接、移动等业务提交规则 |
| setters | 属性编辑器与其 UI 依赖 | 不与 model/core 合并 |
| engine | 默认能力组合、实例创建与销毁、便捷公共门面 | 不合入 core，避免把 UI/X6 依赖带回底层 |

依赖方向保持 model 在底层，core 依赖 model；graph 与 plugins 使用窄应用契约；UI 层通过端口和扩展点组合；engine 作为组合根。领域包不能通过兼容 re-export 反向依赖 core/skeleton。

具体合并的是：端口候选与路由输入、编辑提交规则、注册/销毁所有权。具体拆分的是：GraphManager 内部职责、bridge 的投影与提交、领域定义与 UI contribution。skeleton/react 暂不合包，先证明是否存在真正重复的扩展职责和独立消费者。

## 分阶段交付

i18n 独立前置阶段已提交，建议顺序为 P0 → P1 → P2 → P3 → P4 → P5 → P6；当前已完成 P0、P1，后续阶段待明确执行指令。实施时每阶段独立评审、提交和验收；允许只读分析并行，不同时修改同一契约或 GraphManager。

### 前置阶段：独立 i18n 服务（已完成，提交 `419757d`）

- 新增 `@flow-designer/i18n`：默认共享服务及 `createI18n()` 独立服务，不读取浏览器存储、不依赖 UI/model 或内置词条；`/react` 子入口提供 `I18nProvider` 和 `useTranslate`。
- model 删除旧 i18n exports，消费者迁至新包；原 React `useTranslate` 保留为兼容门面。
- 框架词条拆到 graph/plugins/react/setters/skeleton 的 `src/messages.ts`；场景 header 文案归各 nodes 的 `src/i18n.ts`。
- engine 的 `initializeDesignerI18n(scenarioMessages)` 组合目录并选择初始浏览器语言；`createDesigner` 持有语言持久化订阅及清理。UI 初始化迁到此入口，独立服务仍用底层初始化。
- 注册词条覆盖传入的同名 key、保留其他 key；修正旧 spec 的不覆盖措辞，不改变现有合并语义或放宽测试。
- 完整 designer 本轮仍共享默认服务；独立服务/Provider 可隔离翻译子树，不代表多 editor 全运行时隔离。

验收记录见 `docs/verification.md` 的 2026-11-06 国际化条目：555 项单测、13 项针对性浏览器回归、构建、类型/lint、模块消费均通过。后续 P0–P6 的通过情况单独记录。

### P0：固定行为、接口与性能基线（已完成）

产物与实测记录：[P0 核心重构基线](2026-11-06-core-baseline.md)、`scripts/check-core-baseline.mjs`、固定序列化 fixture。公开消费检查六组通过，完整 Chrome E2E 82/82，生产性能 100/300/500 节点各三次。

- 覆盖 BPMN、ER、ComfyUI，以及 create-node 生成包；区分 engine 便捷入口与直接导入底层包的消费者。
- 固定节点/线 ID、端口、线型、顶点、属性、选中状态及单次手势的历史粒度。
- 为实际高风险路径建立特征测试，不编写仅验证“文件已拆开”的测试。
- 对包实际支持的模块格式及 TypeScript 解析方式建立消费者编译测试；拟新增格式单独评估，不能默认宣称支持。
- 性能同时记录节点数、边数、可见数、真实位移、路由次数、帧间隔、错误和降级数。

验收：已有验证命令可复现；基线失败和波动明确标注，不能借重构修改断言掩盖缺陷。

### P1：拆 GraphManager 内部模块，保持行为（已完成）

保留 GraphManager 公共门面，将内部职责分成投影/注册、连接与路由协调、手势会话、展示、资源管理。复用现有 viewport-input、viewport-culling、adaptive-marker，避免重复抽象。

模块只依赖所需的小接口，不传入完整 GraphManager 作为万能上下文。React root、监听器、计时器和 X6 插件的创建与销毁放在同一所有者内。

验收：保留公开门面、路由策略和持久化格式；121 项 Graph 测试覆盖新增 root 身份清理、模型引用释放、部分初始化失败及异常销毁。全工作区 559 项单测、75 个构建/类型/lint/测试任务通过；完整浏览器 82/82，异常路径完善后针对性复验 14/14。生产大图拆分对比九次采样通过，见验证记录。lint 警告预算 192 降至 188。文件长度不是验收标准。

### P2：收窄应用契约与 X6 边界

- core 定义窄 GraphPort、命令请求/结果及编辑操作快照；model 保留纯领域数据和能力约束。
- PaneConfig/Area 等 UI 契约归 skeleton；X6 专属工具、router、connector、插件能力归 graph。
- graph 发出稳定的最终手势快照，例如节点位置和受影响边的端口/顶点变化；plugins 不再依赖监听器顺序读取实时 cell。
- 首批保留 defineNode 组合体验，不同时清理全部 type-only React。

验收：bridge 无新增 X6 强转和逃逸访问；内部应用、模板同步迁移；保存、恢复和撤销结果一致；core 无 UI runtime 依赖。

### P3：建立实例服务与统一资源所有权

先处理 CommandBus、通知和注册撤销，再覆盖 registry、事件、快捷键及偏好。实例由 engine 创建并显式传入，不引入庞大的通用依赖注入框架。

- 注册返回与注册对象身份绑定的 disposer，覆盖和撤销规则明确，不按名字误删其他实例资源。
- 默认目录可共享只读定义，实例覆盖必须隔离。
- 提供内部 DisposableScope 统一逆序清理和错误汇总，保留各层对自身资源的责任。
- theme/locale 明确实例独立或显式页面共享；根 HTML、localStorage、媒体查询由浏览器适配层处理。
- 命令异步执行和错误可观察；同一文档的编辑顺序明确，不把 Timeline 称为数据库事务。

验收：同页两个实例使用相同命令名/节点类型互不覆盖；销毁 A 不影响 B；焦点快捷键、通知、失败初始化和挂起异步完成均有覆盖。双实例隔离必须实测后才能宣称支持。

### P4：统一编辑提交与图投影

将拖入、双击创建、连线创建节点、连接、重连、移动、顶点修改接入 plugins 的统一编辑应用服务。bridge 分成操作适配和投影协调；core 只提供通用执行机制。

统一流程：采集意图 → 解析与校验 → 确定最终变更 → 单次模型提交 → 投影同步。拖动预览保持临时状态，不逐帧制造持久化事务。

保留已有 owned-object 补偿，不能把所有失败改成整图恢复，以免覆盖同时发生的外部编辑。调度器先明确 flush 和取消边界；Timeline 继续保留在 model。

验收：一次操作对应一次 undo；取消/拒绝无 dirty、历史或选择残留；同 ID 外部替换不会误删；外部并发编辑不丢失；ports、vertices、routing mode 在 save/load、undo/redo 中一致。

### P5：统一路由计划与几何缓存

在前述边界稳定后合并两套路由输入，避免同时重构结构和算法。

- 纯几何内核接收不可变节点/端口/障碍快照，不依赖 DOM 或 X6 cell。
- 统一 RoutePlan 输出最终端口、路径、状态、成本和障碍依赖；区分合法路线、几何阻塞、搜索预算耗尽和旧图兼容降级。
- 准入、预览和最终渲染使用一致的几何版本与结果，缓存随相关节点/端口/尺寸/障碍变动失效。
- 共用候选生成和评分，保留操作策略差异：显式有效连接优先、普通节点可自动换端口、移动按几何调整、命名/类型端口保持语义、旧图加载有兼容策略。
- 先通过 profiling 确定热点，再做增量邻接更新、障碍索引和脏边重算；不先承诺 Worker 或替换渲染器。

验收：端点在 port；水平/垂直 port 保持正确出入线切向；避开节点；新交互保持既定转弯规则；近距离线不消失；普通节点自动换 port 简化路线；自定义 marker/样式保留。障碍节点移动、尺寸变化、缩放、撤销均验证缓存失效。

### P6：清理定义与公共入口，完成交付

- 分离领域 schema/能力与 React view/editor contribution，在上层保留 defineNode 的便捷组合。
- 将 UI setter 注册与浏览器偏好实现从领域层迁出，通知和错误使用领域/应用原因码，由 UI 国际化。
- engine 保留便捷 facade，按实际消费需要提供明确子入口；检查编译产物、CSS 和非浏览器导入。
- 删除已无消费者的旧接口、兼容分支和全局补丁；降低对应 lint warning budget。
- 更新规范、API 迁移说明、中英文公共使用说明和脚手架；把稳定浏览器 smoke 纳入 CI，性能基准使用固定环境独立运行。

验收：无反向依赖或循环兼容导出；领域消费不加载 React/X6/browser globals；三个场景和生成包通过；清理旧入口前有完整消费者证据。

## 必须冻结的用户行为

- Sidebar 在 canvasWorkspace 内浮动；toolbar 居中策略不因 inspector 展开变化，inspector 不遮挡底部工具栏。
- 线名称仅在属性面板编辑，不在画布展示、不双击更名。
- 新建节点默认选中、属性面板展示、双击附近创建、帮助弹窗、滚轮缩放和拖动边缘策略维持现状规范。
- BPMN 开始不入线、结束不出线且有提示；普通节点允许各 port 连线及必要的自动端口调整。
- BPMN 箭头与 ER/ComfyUI 无箭头策略保留；既有路由模式和自定义外观不因 undo/redo 改变。
- 不使用隐藏线、取消正常移动或只渲染少量样本来获得看似流畅的结果。

## 验证与完成标准

此前提交的验证记录见 `docs/verification.md`：542 项单测、79 项浏览器测试、19 个构建任务等是之前实际运行的记录，不代表本计划或未来阶段已通过。后续阶段尚未实施，执行时必须记录新的实际检查结果，不能沿用历史通过结论。

每阶段按影响执行类型、边界、单测、构建和真实浏览器用例；最终执行完整现有验证矩阵。当前 CI 不包含 E2E，P6 才计划补充稳定 smoke 门禁。

性能在同设备、同浏览器、production build、相同视口与数据下对比基线和候选版本，覆盖 100/300/500 节点及 200/600/1000 边，拖动、缩放、平移、fit 后密集可见场景至少重复三次。分别记录初始成本与稳态，不只给平均 FPS。

建议常规 500 节点交互以帧间隔 P95 ≤ 20ms 为目标；fit 后全图密集场景单列预算，以 P0 实测制定门槛。此前该场景存在约 16.7–33.3ms 波动，不能承诺任意硬件和图结构恒定 60FPS。每轮保留全部结果、错误/警告、路由次数及真实节点位移，不能挑最好一次验收。

历史存储优化单独设决策门：只有 profile 证明 checkpoint 内存或耗时成为主要瓶颈，才评估结构共享/增量历史，并另列迁移与恢复计划。

## 兼容、交付与回退

- 每阶段建议拆成 1–3 个职责完整的小提交，避免半迁移状态；契约变动与仓内消费者在同一交付中完成。
- 不通过 model 反向导出 core/skeleton 保兼容。兼容入口放上层且限期移除；底层直接导入需要变更时明确列为迁移项。
- 序列化格式、type ID、端口标识优先保持；如未来必须变化，另立版本迁移方案，不能藏在结构重构中。
- 每阶段记录旧入口、替代入口、消费者和删除条件；不长期保留两套可变事实来源。
- 阶段失败时回退该阶段的完整变更；以前一阶段已验收提交为基线，不用整图运行时恢复掩盖实现缺陷。
- 总调度负责契约、依赖和验收；Sol/Terra 可按互不重叠模块执行。公共接口先固定，同一核心文件只允许一名执行者负责，集成与浏览器验收串行。

完成的定义是：职责有明确所有者、接口可独立验证、行为无回归、性能有可重复证据、旧路径实际清理，而不是目录变多或文件变短。
