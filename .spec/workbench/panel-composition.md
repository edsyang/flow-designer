# Workbench panel composition

## Structure

The React `Workbench` renders a provider-backed editor shell with five skeleton areas: `Header`, `Sidebar`, `Inspector`, `Canvas`, and `CanvasToolbar`. `CanvasToolbar` is overlaid inside the canvas centered along its lower edge and arranges its controls horizontally. It remains outside the graph mount element so graph zoom does not scale the controls. The node library can collapse without disposing its contributions and includes a text search. The inspector remains mounted while hidden so its contextual selection observers can reopen it. The header contains contributed document controls and right-aligned help and language actions, without a node counter. The node library belongs to `CanvasWorkspace` alongside `CanvasArea`; both the library and the inspector remain floating overlays rather than layout columns, so opening the library does not shift or resize the canvas. Double-clicking blank canvas space collapses the inspector and opens a searchable quick-add panel for registered visual node prototypes; double-clicking a node never collapses the inspector. Choosing a node creates it centered at the double-click location and selects it. While the quick-add picker is open the node library is hidden and the inspector is kept; both panels return to their previous visibility when the picker closes.

Apps and plugins extend the shell by adding keyed pane configurations to a named area. These names are the public skeleton API and the matching `data-fd-area` DOM identifiers. The shell should remain a composition mechanism rather than a place for scenario graph or document semantics.

## Responsibilities

- `packages/skeleton` owns `ISkeleton`, `IArea`, `PaneConfig`, editor UI bindings, areas, and reusable field/settings surfaces.
- `packages/react` owns provider/context, hooks, panel rendering, workbench composition, and React error boundaries.
- `packages/setters` supplies reusable property editors registered against model schemas.
- Plugins may contribute controls to extension areas through skeleton APIs.
- Scenario-level commands and document actions belong in `Header`; graph navigation and editing tools belong in `CanvasToolbar`.

Shared React content creation and component detection belong to `packages/skeleton/src/create-content.ts`, exported from `@flow-designer/skeleton`. Both workbench panes and settings use it for functions, React classes, memo, forwardRef and existing elements. Existing elements retain key/ref when props are merged, with computed setting props taking precedence. Registered string/config setters retain their registry lookup and fallback rules. Core no longer exports these helpers or imports React at runtime; see [the import migration](../../docs/core-ui-helper-migration.md).

## UI constraints

- Keep user-interface concerns out of `packages/core` and data serialization.
- Preserve typed access to engine, document, selection, and graph state in React hooks.
- Keep app-specific labels and setup in the scenario app; shared panel layout stays reusable.
- Clean up React roots/listeners when graph or workbench resources are disposed.

## Implementation and tests

Primary implementation: `packages/skeleton/src/skeleton.ts`, `packages/skeleton/src/area.ts`, and `packages/react/src/workbench.tsx` plus `packages/react/src/panels/`.

## Interaction and accessibility

The floating canvas dock contributes one toggle for select and pan modes through the public graph manager interaction API; pan is the default mode. Existing skeleton controls remain extensible. When the public canvas itself has keyboard focus, unmodified Enter opens quick add at the viewport center; form fields and descendant controls do not trigger it. The canvas exposes an Enter shortcut hint. Quick add focuses its search on opening, uses the node library's shape icons in a vertical result list, supports Arrow Up/Down through results, cycles Tab within the panel, and closes on Escape or an outside pointer. Closing returns focus to the public canvas keyboard target captured before the blank-canvas double-click opens the panel; an outside pointer preserves its new focus target. While a node is being created, duplicate submissions are blocked and failures remain visible.

Dock, quick-add and inspector are siblings of the graph mount and use screen pixels, so graph zoom does not change their control sizes. The dock centres in the horizontal workspace to the right of an expanded visible library. A collapsed or hidden library reserves no width and the dock returns to the full canvas centre; inspector disclosure, visibility and size never affect horizontal placement. Dock placement observes library disclosure/visibility and control size, clamps its bounds on narrow canvases, and never changes the canvas viewport, graph transform or node positions. The inspector's maximum height reserves the dock's measured height, its bottom offset, and a 12px gap; longer properties scroll inside the inspector. This reserve follows wrapped dock controls on small windows and is released when the dock unmounts. On narrow windows the inspector leaves room for the library reopen button. The dock stays above an overlapping library, while quick add and modal overlays remain above the dock. Focus rings, stable button dimensions and reduced-motion overrides apply to workbench controls. Microinteractions are limited to control color/background changes; graph nodes have no persistent animation.

Selection exposes properties through the inspector and does not mount a floating copy/delete/deselect action popup. The underlying copy, paste, delete and history commands and scoped keyboard shortcuts remain available. Selecting a connection shows its type editor in the inspector with the localized "connection" heading rather than the registered edge type name, and connections without an editor show an explicit empty state. The connection panel subscribes directly to the translation store: changing language updates the same selected connection's heading and refreshed editor descriptions without changing selection or rewriting the user's property values. Scenario-owned editor descriptions remain scenario-owned metadata and must be refreshed by that scenario's locale integration. Automatic create-and-connect is provided through the canvas blank-drop picker described below; it reuses scenario connection validation before offering a prototype.

The header is composed only from contributed items. The built-in canvas-help and language-switcher plugins independently register and remove their right-aligned controls. Their components and feature styles belong to the plugins package, not the React workbench package. Help opens a labelled modal dialog with a backdrop, trapped Tab/Shift-Tab focus, Escape/outside dismissal, and focus restoration to its trigger. It lists actual canvas, copy/paste, delete, and history operations. Help appears only with a ready graph. Hover, focus, and pressed colors give feedback without moving button targets.

Zoom controls include minus/plus, a keyboard-operable percentage slider, a live percentage output synchronized with graph scale events, and an actual zoom-to-fit action. Dock and slider dimensions remain constant through graph zoom. On narrow workbenches controls use compact stable targets and stay within the canvas bounds.

The library uses searchable, grouped graphic cards; their existing drag handlers remain the creation path. Library and inspector use restrained floating surfaces with shared accent, spacing, field and focus tokens. For initially narrow viewports, the node library starts collapsed at 760px or below and the inspector starts collapsed at 1000px or below. A collapsed library becomes a small floating reopen button instead of occupying a full-height sidebar; the expanded library exposes the same control at its top edge so the library can be collapsed by click instead of only through a bottom affordance. Both panels retain explicit keyboard-accessible controls with expanded state and controlled-content references.

Inspector collapse hides content without unmounting contextual observers. Selecting a different single node with settings automatically reveals its configuration, including on narrow viewports; users may manually collapse the currently selected node's inspector until the next configured-node selection. Selection without settings does not force expansion. Clearing selection programmatically retains an open inspector when document settings exist; without document settings it collapses. A blank-canvas click collapses the inspector when the document exposes settings, and a blank-canvas double-click collapses it in all cases. Node/edge clicks and double-clicks do not trigger these blank-canvas handlers. A collapsed inspector retains its reopen control after widening.

Quick add anchors twelve screen pixels from the blank-canvas double-click point, flips to the other side when its measured size would cross an edge, and clamps inside its owning canvas. Successful quick-add and library-drop creation select the created node through graph/model selection; graph interaction owns the drop bridge. No persistent per-node effects or animation are added.

Dropping a connection drag on empty canvas reuses the same panel: the graph emits `connection:blank` at the drop point and keeps the temporary edge until the picker resolves. Canvas invokes stateless commands registered by the graph plugin through the core command registry; it does not own ID generation, port selection, validation or relation mutation. `canvas.evaluatePrototype` enumerates target-capable ports and performs candidate-phase validation. `canvas.createNode` creates the node at the drop point, checks actual target IDs and ports including route feasibility, and connects the original source port in one transaction (one undo step). Missing ports or a final rejection do not leave a created node or relation. Cancelling, replacing or unmounting the picker removes its temporary edge. `onBlankDrop: "ignore"` does not enter this workflow.

Capability rejection keeps the picker visible with an explained empty state including the source's current display name. A completed rejected drop produces one localized warning rather than hover-time toasts. Legacy routing degradation is a separate warning: graph frame batches are shown once per loaded document baseline, without treating old diagram data as a rejected connection or dismissing the picker. Graph event subscriptions and command registrations have owning cleanup paths; if the creation command is unavailable, the picker shows an error without mutating data.

Scenario edge schemas own creation defaults. BPMN initializes a sequence flow's `name` to its registered sequence-flow name; generic data links and relations declare their own names. A schema declaring `name` uses `props.name` as canonical, including an explicit empty string; label-only legacy data remains readable when that canonical field is absent. Other schemas use `props.label`, even if an unrelated `name` property is present. Connection names are metadata edited only in the property inspector, which synchronizes an existing legacy label alias. The canvas does not display connection names, and double-clicking a connection does not open a name editor, node editor or quick-add picker. The former canvas edge-label plugin and its public export are removed. Defaults apply only at creation: changing locale or reprojecting/loading a relation never replaces a user's stored name.
